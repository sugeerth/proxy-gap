Evaluation-driven post-training

Judge bias is not just noise.
It is a forecast.

Everyone knows LLM judges over-reward long, agreeable answers. The usual response is to treat that as measurement error and try to scrub it out. This project takes the opposite view: measure the bias precisely, and it tells you exactly how much optimisation pressure your post-training run can survive before it starts destroying the quality it was meant to improve.

A closed form connects the two. Everything below is reproduced from source by make all — offline, deterministic, no API key.

The mechanism, in three lines

A response has a latent true quality q, a standardised length L, and an agreeableness S. The truth is single-peaked in length — some elaboration helps, too much hurts. The judge is monotone in length.

true r* = q − a·(L − L*)² − c·S proxy r̂ = q + β·L + β_S·S + ε

That is the whole disagreement. The proxy is locally right — it increases in true quality — and globally wrong, because it never turns around. Optimise hard enough against it and you walk straight past the peak of the truth. β is not a metaphor here: it is the coefficient that the bias probe measures, on real judge outputs, with a confidence interval.

The claim. Under best-of-n selection, the optimisation pressure at which true quality peaks is fixed by the judge's bias coefficient alone:
ln n* = (v / 2) · [ L*/β + (1 − c·β_S) / (2 a β²) ]² v = 1 + β² + β_S² + σ²
In the regime where the true optimum is displaced from the base policy (L* > 0), this collapses to ln n* ∝ β⁻² — halve a judge's verbosity bias and you roughly quadruple the KL budget you can safely spend. When the optimum coincides with the base policy (L* = 0), the exponent is −4.

Figure 1 — The proxy gap opens

One baseline sweep. As best-of-n pressure rises, the judge's score climbs monotonically and never warns you of anything. True quality rises, peaks, and turns over. The vertical rule is the closed form's prediction of where the peak should be — computed from β, a, L* and σ, with no access to the simulation.

Figure 2 — The Bias–Budget Law

Sweep β across an order of magnitude and record where the true-quality peak lands each time. On log–log axes the relationship should be a straight line whose slope is the exponent the theory predicts. Both regimes are shown; the fitted exponent and its bootstrap interval are reported next to the theoretical value, agreeing or not.

Figure 3 — What actually closes the gap

Four interventions, run through the same sweep. The result worth internalising is the negative one: averaging more judges does not help. An ensemble shrinks σ, and σ is not what moves the peak — β is. If every judge in your council shares the same verbosity prior, the council inherits it in full, and you have bought precision around the wrong number.

What this changes in practice

Before training

Run a bias probe first

An OLS regression of judge score on the biased feature, holding true quality fixed, costs minutes and returns β with an interval. That number sets the KL budget before you spend a single GPU-hour.

During training

Budget in KL, not in steps

Step count is not the controlled variable; distance from the base policy is. Reporting a run as "1000 steps" says nothing portable; reporting it as "KL 1.8 of a predicted 2.4 budget" does.

When choosing a fix

Debias, don't ensemble

Ensembling attacks variance; the peak is set by bias. Length-controlled scoring, position swapping, and reference-anchored rubrics move β. More judges do not.

In the eval report

Publish β alongside the score

A leaderboard number without its judge's bias coefficients is not reproducible — the same benchmark under a differently-biased judge rewards a different model.

What this is not

Read this before citing any number above

These are simulations, not measurements of a real model. The response population is generated from the feature model above, not sampled from a language model. That buys exact ground truth — you cannot observe q for a real system, which is precisely why reward hacking is hard to study empirically — and it costs external validity. The law is derived and validated within this model. Whether real judges and real policies obey it is an open empirical question, and the honest framing of this repository is that it makes that question testable, not that it answers it.

Three assumptions do real work and would each break the exponent if violated: Gaussian features, linear judge bias, and quadratic true-reward curvature. Best-of-n is also a stand-in for policy-gradient optimisation; it shares the KL bookkeeping but not the dynamics.

A real backend is included (proxygap.models.anthropic_backend, Claude Opus 5) so the same probes can be pointed at real generations. Doing that properly — with human-anchored quality labels rather than a proxy for q — is the obvious next study, and it is not done here.

The rest of the platform

The law is the headline, but it sits on a full evaluation stack — because a prediction about judges is only worth as much as the benchmark and statistics underneath it.

Evaluation stack

Does the benchmark measure anything?

2PL item calibration with parameter recovery, contamination probes, judge bias and position bias, calibration curves, council with veto, robustness perturbations, failure mining, and the human annotation protocol.

 Statistics

Is the difference real?

BCa bootstrap with verified coverage, paired permutation tests, cluster-robust standard errors, BH-FDR across many metrics, power and MDE, CUPED variance reduction, always-valid e-values, and a CI gate that does not cry wolf.
