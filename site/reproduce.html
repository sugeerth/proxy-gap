Reproducibility

Run every number yourself.

Every figure on this site is written by proxygap all into site/data/*.json, and the site reads nothing else. There is no hand-entered number anywhere in the HTML. This page is the operating manual: the commands, the seeding discipline that makes them repeatable, the CI job that keeps the claim true, and an explicit list of what the results do not establish.

1. Quickstart

Three commands from a clean checkout. make all installs the package, runs the test suite, executes every experiment, and rewrites site/data. 

git clone https://github.com/sugeerth/proxy-gap
cd proxy-gap
make all          # install, test, run every experiment, write site/data
open site/index.html
No API key, no network, no GPU. The experiments are Monte Carlo over a small feature model; the dependencies are NumPy, SciPy and scikit-learn. It runs on a laptop in minutes. The site itself is static and opens from file:// — site/data/bundle.js inlines the JSON so no local web server is needed either.

The individual commands

Each subcommand runs one thing and prints it. All of them accept --seed; the default is the run seed recorded in manifest.json.

commandwhat it does
proxygap sweep One baseline best-of-n sweep, printed as a table of n, KL, proxy score, true reward, the gap between them and the mean selected length, with the true-quality peak marked.
proxygap law Fits the Bias–Budget Law on two β grids and prints three numbers per grid: the Monte Carlo exponent with its bootstrap interval, the closed form's own local slope over the same window, and the idealised β → 0 asymptote.
proxygap probe Measures each simulated judge's length-bias coefficient from its outputs and prints it beside the coefficient it was declared with, with a 95% interval and a p-value. This is the estimator that would be pointed at a real judge.
proxygap gate Runs the release gate over its demo scenarios and prints pass/block, the reason, and which individual comparison did the blocking.
proxygap verify The self-check. Compares the closed-form KL* against the simulated KL* over a grid of β and L*, excludes right-censored rows, and exits non-zero if the worst comparable row deviates too far.
proxygap all --out site/data Runs every experiment, writes one JSON per artifact plus manifest.json, and exits non-zero if any artifact failed. proxygap run <artifact> does a single one.

2. Determinism

The seeding rule is a single sentence: every stochastic function takes an integer seed and builds its generator through proxygap.rng.gen. Nothing calls np.random at module level, nothing reads global state, and no generator is shared across component boundaries.

Components draw from named substreams rather than from a shared generator. SeedBank(root).seed(name) XORs the root seed with a BLAKE2b digest of the component name, so a substream depends only on the run seed and its own name. That property is the point: adding a new experiment, or reordering the existing ones, does not shift any other component's draws, so a figure that was not touched does not change.

gen(seed) -> np.random.default_rng(seed) substream(seed, name) -> seed XOR blake2b(name) # stable, order-independent SeedBank(root).rng(nm) -> gen(substream(root, nm))

Given the same seed and the same NumPy version, output is bit-identical. The NumPy version is part of the contract, not a footnote: Generator's bit stream is stable across platforms, but the distribution methods layered on top of it are only guaranteed stable within a version series. That is why the manifest records it.

The fixture a fresh run has to reproduce

These are the baseline sweep's recorded values, read live from site/data/sweep.json. Re-run make all on the same NumPy and every one of them should come back unchanged.

3. What CI enforces

.github/workflows/ci.yml has two jobs, and the second one is the interesting one.

The test job is ordinary: a matrix over Python 3.10 and 3.12, pip install -e ".[dev]", then pytest -q. The suite collects 613 tests across fifteen modules at the time of writing, and pyproject.toml promotes RuntimeWarning to an error, so a silent overflow or an invalid divide inside a statistical routine fails the build instead of quietly producing a NaN.

The reproduce job is the one that defends the claim this page makes. It runs proxygap verify, then proxygap all --out site/data, then reads back manifest.json and fails if any artifact's ok flag is false, printing that artifact's recorded traceback as a GitHub error annotation.

Why this matters more than the test count. Unit tests check that functions behave. They do not check that the website's numbers still come out of those functions. A repository can pass every test and still be showing a chart generated by code that was deleted six commits ago. The reproduce job closes that gap: the claim that every number regenerates from source is itself a test, and it runs on every pull request.

What proxygap verify actually checks

The closed form predicts KL* from (β, β_S, a, L*, σ) alone, with no access to the Monte Carlo. Plotting the prediction against the observed peak puts agreement on the y = x line. This is the only chart on this page, and it is here because it is the check, not a result.

Right-censoring is treated as missing data, not as disagreement. When the predicted optimum lies beyond the largest n the sweep visits, the observed peak is pinned to the endpoint by construction; that row says nothing about the prediction, so verify excludes it from the tolerance check and reports how many it excluded. Scoring those rows would manufacture an agreement that was never measured.

4. Using a real model

proxygap.models.anthropic_backend implements the same Model protocol as the synthetic fleet — respond(item, seed) -> Response — against Claude Opus 5, so anything that consumes the protocol (the item bank, the judge, the probes, the perturbation harness) accepts it without modification. 

pip install "proxygap[claude]"
export ANTHROPIC_API_KEY=...        # or ANTHROPIC_AUTH_TOKEN

python - <<'PY'
from proxygap.models.anthropic_backend import ClaudeModel, available
print("credential + SDK present:", available())
model = ClaudeModel()               # constructing it touches nothing
PY

It is an optional dependency and the module is import-safe without it: nothing is imported at module scope, construction opens no client and touches no network, and the SDK is imported lazily inside the first call that needs it. available() returns true only when the SDK imports and an environment credential resolves — a login profile on disk is deliberately not consulted, because a function whose answer depends on machine state no test can control is not a function you can rely on.

The features it produces are measured proxies, not ground truth

This is the whole reason the core experiments on this site are simulated, so it is worth being blunt about. A synthetic response knows its latent quality q because q is what generated it. A real model does not, and no adapter can recover it. What the backend writes into Response.features is a set of cheap observables:

  • quality — half normalised containment of the item's reference string in the reply, half a self-consistency score (token overlap between the reply's marked intermediate claims and its own final claim), rescaled to roughly [−1, +1]. It is a stand-in for a grader, not a grader. It credits a reply that names the right answer inside a wrong argument.
  • length — standardised token count against fixed calibration constants, so a single response lands on the same scale as the synthetic fleet rather than on a scale estimated from its own sample.
  • sycophancy — agreement-marker hits per sentence from a fixed lexicon, standardised. A lexicon count is a blunt instrument: it fires on a warm but accurate reply and misses agreeable content phrased outside the lexicon.
  • confidence — one minus a hedging-marker rate, clipped to [0, 1].

Every one of these is a noisy observable standing in for something unobservable. Substituting a proxy for q and then measuring how much a judge's bias distorts q is circular — the thing being measured and the yardstick share their failure modes. That circularity is exactly why reward hacking is hard to study empirically, and exactly why the experiments behind the Bias–Budget Law are run on a generative model where q is known by construction. Breaking it needs human-anchored quality labels, which is a different and more expensive study than the one this repository runs.

One further property, stated because it surprises people: the seed argument cannot make a hosted model deterministic. The API takes no seed. It is carried onto the record for replay bookkeeping only, and two calls with the same seed will differ. Reproducibility guarantees on this page apply to the offline path.

5. Limitations

What the simulations do not show

These are simulations, not measurements of a real model. The response population is generated from the feature model in docs/THEORY.md §1, not sampled from a language model. That buys exact ground truth and costs external validity. The law is derived and validated within this model. Whether real judges and real policies obey it is an open empirical question; the honest framing is that this repository makes the question testable, not that it answers it.

Three assumptions do real work and would each break the exponent if violated: Gaussian features, linear judge bias, and quadratic true-reward curvature. Best-of-n is also a stand-in for policy-gradient optimisation; it shares the KL bookkeeping but not the dynamics.

Two more, specific to the numbers on this site. First, the fitted exponents are shallower than both the asymptote and the closed form's own local slope over the same β window (see the figures below); the sweep's log-spaced grid is coarse where n* is small, which compresses the estimate toward the grid. Second, the closed form is systematically low against the simulation in the windows shown — it is a usable lower bound on the safe budget in this model, not a calibrated point estimate.

Two corrections integration testing found

Both of these were found by running the derivation against its own simulation and refusing to explain away the mismatch. They are recorded here rather than quietly patched, because a derivation that survived contact with a Monte Carlo is worth more than one that was never tested against anything.

(a) The √(2 ln n) substitution for E[max] was wrong by about 19% at n = 300. An earlier version of docs/THEORY.md sanctioned approximating the expected maximum of n standard normals by √(2 ln n) inside the analytic prediction. Because ln n scales like the square of that quantity, a 19% error in the expected maximum becomes roughly an order of magnitude in the predicted n*. With the approximation in place the closed form appeared to miss the simulation by a factor of four — the theory was right and the inversion was not. The computational path now uses the exact expected maximum (expected_max_normal, by numerical integration) and inverts it via Blom's order-statistic approximation, m_n ≈ Φ⁻¹((n − 3/8)/(n + 1/4)), accurate to well under 1% for n ≥ 10. √(2 ln n) now appears nowhere in the code. See docs/THEORY.md §2.
(b) The two regimes were documented backwards. The original table labelled β⁻² the small-β limit. It is the opposite. As β → 0 the curvature term 1/(2aβ²) grows like β⁻² while the displacement term L*/β grows only like β⁻¹, so the curvature term always dominates at small β and ln n* ∝ β⁻⁴ there, even when L* > 0. The β⁻² behaviour is the large-β, length-dominated regime. The crossover sits near β ≈ (1 − c·β_S)/(2 a L*), which is at infinity when L* = 0 — a coincident optimum is β⁻⁴ everywhere. See docs/THEORY.md §4.

The second correction is also why the honest null on the law figures is the closed form's own local slope over the observed β window rather than the idealised exponent. The v = 1 + β² + β_S² + σ² prefactor is not constant in β, so over any finite window the local slope is shallower than the asymptote. Both numbers are reported by proxygap law, side by side, and the fit is reported whether or not it agrees.

6. Repo map

Ten packages under src/proxygap/. The dependency rule is that report/ does no science — if a number appears on this website it was computed in one of the others and report/ only moved it.

packagewhat lives there
bench/ The synthetic item bank, 2PL item calibration with parameter recovery, contamination probes, and a benchmark-health report that asks whether the bank measures anything at all.
models/ The one Model protocol, the deterministic offline fleet that satisfies it, and the optional Claude backend that satisfies it against a real API.
score/ Deterministic surface-form scorers (the baseline every judge is compared against), the LLM-judge simulator and its bias probes, council aggregation with veto, and calibration metrics.
stats/ BCa bootstrap, paired permutation tests, cluster-robust standard errors, BH-FDR, power and MDE arithmetic, CUPED, and always-valid sequential testing.
robust/ Semantics-preserving perturbations — plus one deliberately semantics-breaking control — and the brittleness score that separates ability from prompt-surface artefact.
posttrain/ The reward model of THEORY.md §1, best-of-n as the optimisation-pressure knob, the sweep and the law fit, and the four mitigations.
failure/ A failure taxonomy, a deterministic classifier for it, and the miner that turns a pile of wrong answers into a ranked fix list.
human/ The annotation protocol (gold seeding, drift detection), inter-rater reliability, and the human-versus-judge budget tradeoff.
gate/ The release gate: the component that actually blocks a ship on a real regression, and declines to on a noisy one.
report/ Runs every artifact, records which ones failed, and writes site/data/*.json. No science.

Three modules sit outside the packages: rng.py (the only generator constructor), types.py (the schema canon every record conforms to), and cli.py (the entry point above). docs/THEORY.md is the shared reference every module that touches rewards must match; docs/API.md pins the public signatures.
